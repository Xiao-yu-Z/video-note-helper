# 常见问题与排查（FAQ）

下面汇总高频报错与对应解决方案。所有功能均依赖本地运行环境，遇到问题时优先检查浏览器扩展权限与平台页面状态。

---

## 一、字幕提取失败

**Q1：提示「该视频暂无公开字幕 / 未找到公开字幕」**
- 在播放器中**手动开启字幕（CC）**后重试；部分视频本身没有字幕。
- YouTube：确认字幕语言已在播放器中选择；自动生成字幕（CC）需视频已启用。
- B站：部分老视频仅有 AI 字幕，等待加载完成后再提取。
- 百度网盘：请先在播放器开启「AI 字幕」，并播放一段时间让字幕加载。

**Q2：提示「未能从链接中识别 BV 号 / 未能获取 cid」**
- 请确认当前处于 B站**视频播放页**（URL 含 `BVxxxx`），而非个人主页或列表页；刷新页面后重试。

**Q3：字幕内容乱码或为空**
- 多为网络/接口临时异常，点击「提取字幕」重新尝试；B站接口偶发限流，稍候即可。

**Q3.1：之前「字幕无法提取」，现在仍失败 / 一直 Loading**
- 早期版本在内容脚本里直接 `fetch` 平台接口，会被浏览器**跨域（CORS）拦截**；B站 `x/player/wbi/v2` 还需 **WBI 签名**（依赖 MD5）。v1.0.0 已修复：所有接口请求改由**后台 Service Worker 代发（proxyFetch）**绕过 CORS，B站主路径改为 **WBI 签名请求**，并保留「免签名 / 旧版接口」两层兜底。
- 若仍失败，优先排查：
  1. 是否处于**视频播放页**（B站 URL 含 `BVxxxx`、YouTube 在 watch 页、百度网盘在播放页）；
  2. 视频是否**确有公开字幕**（AI 字幕需在播放器手动开启后加载）；
  3. 打开控制台（F12 → Console）看是否有 `-412 / -404 / 网络错误`，多为平台限流或登录态缺失，刷新或登录后重试。
- WBI 签名依赖的 MD5 已替换为经验证的 blueimp/JavaScript-MD5 实现（此前自写 MD5 在第 4 轮有常量错误，会导致所有 B站签名请求失败）。

## 二、大模型 API 调用失败

**Q4：提示「密钥错误（401）」**
- 检查设置中的 `API Key` 是否完整、有无多余空格；部分平台需要在 Key 前加 `Bearer ` 前缀（本项目已自动添加，请勿重复填写）。

**Q5：提示「额度不足或被限流（429）」**
- 账户余额不足或触发速率限制；充值或降低请求频率后重试。

**Q6：提示「请求超时 / 网络错误」**
- 检查 `API Base URL` 是否正确（填到 `/v1` 即可，**无需**包含 `/chat/completions`；若误填了完整端点，扩展会自动识别）。
- 本插件当前标签页的 `base_url` 需可被浏览器直接访问；若是本地模型（如 Ollama），确认服务已启动且端口可访问。
- 某些供应商需要额外请求头（如 `api-version`），当前版本未内置，可反馈需求。
- 扩展内置**自动重试**：超时、429、5xx、网络抖动会按0.8s → 1.6s → 3.2s 指数退避重试（次数见设置页「失败重试次数」）。若频繁超时，可上调「请求超时」与「减少字幕送入模型的字符上限」。

**Q6.1：报错 `Unexpected token 'd', "data: {"id"... is not valid JSON`**
- 这是**接口返回了 SSE 流式响应**（形如 `data: {"id":...}`）而非标准 JSON 所致，常见于 one-api / new-api / Ollama / 各类中转网关——它们可能忽略 `stream: false`。
- **已修复**：扩展改为先读文本再容错解析，自动识别 SSE 并拼接 `delta.content`，同时也兼容被 ` ```json ` 包裹或前后带杂讯的响应。若你仍看到旧的 JSON 报错，请在扩展管理页**点击「重新加载」**以更新到最新代码。

**Q6.2：提示「后台响应超时」或「扩展通信中断」**
- MV3 的后台 Service Worker 空闲会被浏览器回收，长任务期间通道可能被关闭。
- **已修复**：内容脚本对生成/同步/导出分别设置了独立的等待上限，并在通道类错误上**自动重连一次**。若仍出现，点击扩展图标刷新页面后重试。
- 长视频建议在设置页调高「请求超时」，并调低「字幕送入模型上限」（默认 24000 字，超出部分会保留首尾后截断）。

**Q6.3：提示「模型没有生成任何内容（completion_tokens=0）」** ← 最常见
- 含义：接口**正常接受了输入**（错误信息里会给出 `prompt_tokens`），但模型一个 token 都没输出。这**不是**扩展的解析问题。
- **长视频出现该错误的正解：开启「长视频自动分段生成」**（设置页第⑤节，默认开启）。字幕过长 → 提示词超上下文 → 模型无输出，这是长视频失败的根因；分段后每个请求都很小，从根本规避该问题。
- 若仍出现，按可能性排序排查：
  1. **单段仍然过长**：调低「每段字幕字符数」（如 6000 → 3000）。
  2. **账户余额 / 配额不足，或该模型未开通**：到服务商控制台确认。部分网关在这种情况下不报错，而是返回一个空补全。
  3. **模型名不存在**：例如 `deepseek-v4.1-flash` 这类名称多为第三方中转的别名，官方并无此模型。建议先用官方名（`deepseek-chat` / `deepseek-reasoner`）验证连通性。
  4. **参数组合不被支持**：换用设置页的「测试大模型连接」→ 它会依次尝试标准参数与兼容模式。
- **扩展已内置自动恢复**：遇到该错误会先**自动精简提示词（字幕上限减半）重试**，仍失败再**放宽 Token 预算**重试。多数情况无需手动干预。
- **若三次都失败**：错误信息末尾会附上「本次自动排查记录」（逐次列出输入 tokens、字幕上限、max_tokens）。**如果输入已明显变小却仍零输出，就可以排除"提示词过长"，问题在模型侧**——按错误里列出的三项逐一确认（模型名是否真实存在 / 余额与配额 / 换个已知可用的模型）。
- 面板上有「**复制诊断信息**」按钮：一键复制配置 + 最近一次错误 + 原始响应开头（密钥已脱敏），可直接粘贴反馈。
- 兜底建议：把「最大输出 Token」设为 4000 以上，并换用上下文 ≥ 64k 的模型。

**Q6.3.1：长视频生成很慢 / 中途失败**
- 开启分段生成后，长视频会按段多次调用模型（如 5 段即 5 次请求），总耗时必然更长，但**每一步都更稳**——面板会显示「正在生成第 i/N 段…」，等待期间还有「模型生成中…（已等待 Ns）」心跳。
- 想更快：调大「每段字幕字符数」以减少段数（代价是每段请求更大）；想更稳：调小它。
- 某一段失败时，**其余段落的结果仍会保留**，笔记末尾会用 `> [!warning]` 标出缺失的时间段，不会整篇白干。可据此单独重试。

**Q6.3.2：提示「后台无响应（已 N 秒未收到任何进度）」**
- 该超时衡量的是**沉默时长**，不是总耗时——只要后台在推进（每段、每批配图都会推送进度），生成多久都不会被判超时。出现此提示意味着后台**真的长时间没有任何动静**了。
- 常见原因：浏览器回收了扩展后台（MV3 Service Worker）。→ 点击扩展图标刷新页面后重试。
- 若反复出现于超长视频：调小「每段字幕字符数」让单次生成更快完成，或调大「请求超时」。
- 反向提示：如果只是「生成很慢」但面板上的等待秒数在持续增长，那是**正常**的，不要刷新，耐心等待即可。

**Q6.4：提示「模型只输出了思考过程、没有生成正文」**
- 用的是**推理模型**（deepseek-r1 / o1 / qwen-thinking 等），思考过程把 `max_tokens` 吃光了。
- 扩展会自动把 Token 预算翻倍重试；仍失败请把「最大输出 Token」调到 4000 以上，或改用非推理模型。
- 扩展会把思考内容与正文**严格分离**，绝不会把推理过程写进笔记。

**Q6.5：提示「流式响应共 N 个分片：有内容 x / 仅用量统计 y / 解析失败 z」，但没有文本字段**
- 说明接口返回了分片，但内容不在扩展预期的字段上。**错误信息会直接列出实际出现的字段名**，把它反馈上来即可针对性适配。
- 若「解析失败」计数大于 0，说明有分片无法解析（多为网关输出非标准 SSE），错误信息会附带首个失败分片的开头，便于定位。
- 注意：「仅用量统计」（`choices: []` + `usage`）是标准的流收尾分片，属正常现象，不是错误。

**Q6.6：提示「模型参数不兼容，正在自动调整请求参数重试」**
- 部分模型（o1 / gpt-5 系列）只认 `max_completion_tokens`，且不接受自定义 `temperature`。
- **已修复**：扩展检测到这类 400 报错时会自动改写参数并立即重试一次，无需手动干预。设置页「测试大模型连接」也会依次尝试「标准参数」与「兼容模式」，两者都失败才报错。

**Q6.7：设置页测试显示失败，但实际生成能用**
- 旧版测试探针只发 8 个 token，遇到推理模型必然返回空。**现已修复**：探针与真实生成共用同一套解析与参数兼容逻辑，并能区分「连不上」「连上但无正文」「零输出」几类原因。

**Q6.8：本地模型（Ollama / LM Studio）**
- Base URL 需填到 `/v1`（如 `http://127.0.0.1:11434/v1`），只填到端口取不到内容。
- 扩展同时兼容 Ollama 原生响应格式（`message.content` / `response`）。

## 三、Obsidian 同步失败

**Q7：提示「Obsidian 未启动 / 接口不通」**
- 确认 Obsidian 已打开且 **Local REST API** 插件已启用。
- 确认设置中的「接口地址」与插件显示一致（默认 `http://127.0.0.1:27123`）。
- 检查防火墙是否拦截了该本地端口。
- 可在扩展设置页点击「**测试 Obsidian 连接**」，它会区分「连不上（服务未起/端口被拦）」与「密钥错（401/403）」两类原因。
- 同步前扩展会先做一次连通性预检，避免逐张图片重复失败；所有 Obsidian 请求均带独立超时（默认 20s），不再无限挂起。

**Q8：提示「密钥错误（401）」**
- 重新在 Obsidian 的 Local REST API 插件中生成 API Key，并粘贴到扩展设置。

**Q9：提示「目录不存在（404）」**
- 扩展写入时会带 `Create-If-DoesNotExist`，**多数情况下会自动创建目录**；若仍报404，扩展会自动尝试补建目录后重试一次。
- 仍失败时请确认笔记目录名是否包含 Obsidian 不允许的字符，或库内路径与设置不一致。

**Q10：同步成功但 Obsidian 中找不到笔记**
- 检查「笔记保存目录」「按平台建子目录」设置，笔记实际位于 `库根/笔记目录/平台子目录/` 下；同步成功提示中会给出完整路径，可直接复制打开。

## 四、截帧 / 配图相关

**Q11：点击「插入当前帧」没有反应或报错**
- 确认页面处于视频播放页且 `<video>` 已加载；部分浏览器对跨域视频的 canvas 读取会受限，本插件会**自动回退为截取可见标签页画面**（即播放器所在窗口画面），仍可作为配图。
- 若回退截图为空，请确保播放器画面在屏幕可见区域，再重试。

**Q12：自动截帧后视频进度被改动**
- 自动模式会拖动播放进度以截取各章节起始帧，结束后会回到开头；属正常现象。

**Q12.1：YouTube 上「自动按章节截帧」卡住不动**
- YouTube 等流媒体使用 MSE，`video.duration` 常常是 `Infinity`，早期版本会因此计算出无效时间点，且无限等待 `seeked` 事件导致永久卡死。
- **已修复**：时长不可用时自动切换为「连续采样」模式（保持播放并按间隔抓帧）；每次 seek 增加 4s 超时兜底，超时后直接截当前画面。

**Q12.2：点按钮没反应 / 重复点击会不会重复请求**
- 生成、同步、导出等操作执行期间会**自动禁用面板按钮**，防止连点导致多个大模型请求并发叠加而超时。

## 五、安装与权限

**Q13：加载扩展后工具栏没有图标 / 面板不出现**
- 确认加载的是 `src/` 目录（含 `manifest.json`），而非仓库根目录。
- 确认扩展已「启用」；在支持的视频页刷新一次。
- 检查浏览器是否为较新版本（Manifest V3 需 Chrome 88+ / Edge 88+）。

**Q14：担心隐私 / 数据上传**
- 本项目**全程本地运行**：字幕、截图、配置、生成内容均仅保存在你的浏览器或本地 Obsidian 中，无任何中转服务器，插件不收集任何用户信息。详见 README 免责声明。
