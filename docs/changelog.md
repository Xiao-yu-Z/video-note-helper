# 更新日志（Changelog）

本项目遵循 [语义化版本（Semantic Versioning）](https://semver.org/lang/zh-CN/) 规范：版本号格式为 `主版本.次版本.修订号`。

## [1.1.2] - 2026-10-03

### 优化 — 长等待期间的进度可读性
分段生成的单段可能耗时数分钟，此前只显示「模型生成中…（已等待 20s）」，用户无法判断整体进度，容易误以为卡死。

- **心跳同时给出本段等待与总耗时**：「第 2/4 段 模型生成中…（本段已等待 20s，总耗时 95s）」。
- **段落进度更明确**：「长视频已自动分段（共 4 段）· **已完成 1/4 段**，正在生成第 2/4 段…」——一眼看清整体走到哪了。
- **结束时汇报总耗时**：「全部 4 段生成完成（总耗时 312s）」/「完成，但有 1/4 段失败（已标注在笔记中，总耗时 288s）」。

设计意图：长任务里用户最大的焦虑是「不知道还要等多久 / 是不是卡住了」。只要进度在推进且能看出比例，等待就是可接受的。

## [1.1.1] - 2026-10-03

### 修复
- **`后台响应超时（300s）`——分段生成引入的回归**：内容脚本对「生成笔记」使用 300s **固定总时长**超时，而分段生成会连续调用模型多次（5 段各需数分钟），总耗时必然超过 300s，导致长视频在即将成功时被判超时。这是 v1.1.0 引入的问题。
- **超时改为衡量「沉默时长」而非总耗时**：后台每完成一段都会推送进度，内容脚本收到推送即**重置看门狗**；只有长时间完全收不到任何消息（后台真被回收）才判超时。沉默上限也由「请求超时 + 60s」动态推导，不再硬编码 300s。
- **后台新增 20s 心跳**：等待模型响应期间定期推送「生成中…（已等待 Ns）」，既让看门狗知道后台仍在工作，也通过 `chrome.*` 调用**保活 MV3 Service Worker**，避免长任务被浏览器回收。
- **完整保留段序号**：心跳提示会带上当前段（如「第 2/5 段 模型生成中…（已等待 40s）」）。
- **同步 Obsidian 也推送进度**：分批上传配图时显示「上传配图 3/6…」，同步过程的看门狗同样得到重置。
- 超时错误提示改为可操作建议：指出「已 N 秒未收到任何进度」，并建议调小「每段字幕字符数」以缩短单次耗时。

## [1.1.0] - 2026-10-03

### 新增 — 长视频分段生成（解决长视频生成失败的根因）
长视频的字幕动辄数万字，提示词必然超出模型上下文，导致模型「零输出」。此前的做法（截断字幕或减半重试）只是权宜之计：截少了仍超上下文，截多了丢内容，且阈值无法预判。本版改为**从根本上规避**：

- **自动分段**：字幕总长超过「每段字符数 ×1.2」时，按字幕条目边界切成多段，逐段调用模型后自动合并。每个请求都很小，永远不会超上下文，信息保留比截断更完整，同时大幅降低超时概率。
- **段间不重复、不越界**：分段模式下系统提示会告知「第 N/M 段」，明确要求只整理本段内容、不复述其它段落，并使用贴合内容的真实章节标题（而非「第一部分」这类占位标题）。**总结 Callout 只由末段输出**，避免每段都写一遍 Key Takeaways。
- **截图编号全局一致**：截图按播出时间分配到各段，且**始终使用全局编号** `frame_N`，不会因分段而重排导致笔记配图错位。
- **单段失败不放弃整篇**：某段失败时其余段落结果仍保留，并在笔记末尾以 `> [!warning]` 显式标注缺失的时间段；仅当首段就失败（大概率是配置问题）时才整体报错并指明是第几段失败。
- **进度可见**：面板实时显示「长视频已自动分段（共 N 段），正在生成第 i/N 段…」。
- **新增设置项**：`长视频自动分段生成` 开关、`每段字幕字符数`（默认 6000）、`最多分几段`（默认 10，超出会自动放大每段预算，避免一次发出过多请求）。
- 新增可复用纯函数模块 `src/shared/chunk.js`（`splitSubtitleChunks` / `assignFramesToChunks` / `timeToSec`），无 chrome/DOM 依赖，便于单测。

### 修复
- **分段切分的段数上限不严格**：`ceil(total/maxChunks)` 未考虑贪心切分按条目边界断开造成的取整损耗，实际段数常比上限多 1~2 段。现改为迭代放大每段预算直到真正满足上限。此问题由单元测试发现（断言 `≤6` 却得到 7 段）。

## [1.0.2] - 2026-10-03

### 修复
- **零输出的最终报错现在给出决定性结论**：三次恢复都失败时，错误信息会附「本次自动排查记录」（逐次列出输入 tokens / 字幕上限 / max_tokens）与原始响应开头。**若输入已明显变小却仍零输出，直接判定"问题不在提示词过长，而在模型侧"**，并列出三项待确认事项（模型名是否真实存在 / 余额与配额 / 换个已知可用模型），避免用户在错误方向上反复调整。

### 新增
- **「复制诊断信息」按钮**（面板）：一键复制运行配置 + 最近一次失败详情 + 原始响应开头（密钥脱敏为 `前6位…后4位（长度N）`），可直接粘贴反馈。后台新增 `getDiagnostics` 接口，失败详情持久化在 `chrome.storage.local.lastFailure`；错误对象携带 `raw` 字段（截断 4000 字符）供导出。
- 恢复链路的状态提示会实时显示当前动作与输入规模（如「模型未产出内容（输入约 16195 tokens），正在精简提示词后重试…」）。

## [1.0.1] - 2026-10-03

### 修复
- **`模型没有生成任何内容（completion_tokens=0）`**：实测发现这是「零输出」而非解析问题——接口正常接受了输入（如 `prompt_tokens=16195`），但模型一个 token 都没产出，此前会被笼统报成"没有找到文本字段"。现单独识别该模式，并把 `prompt_tokens` 一并输出，按「输入超出上下文 / 余额或模型未开通 / 模型名不存在 / 参数不兼容」排序列出可操作对策。**并内置自动恢复**：先自动精简提示词（字幕上限减半）重试，仍失败再放宽 Token 预算重试。
- **解析失败的分片被静默丢弃**：SSE 解析中，无法解析的分片暂存于 `pending` 后，会被下一个 `data:` 行或空行直接覆盖丢弃，导致内容"凭空消失"且诊断信息里毫无痕迹。现改为**计入「解析失败」统计并记录首个失败分片开头**。
- **`choices: []` 用量统计分片被误判**：正常流末尾的用量分片（`stream_options.include_usage`）会污染"无文本字段"诊断。现单独计数，不再误报。
- **Ollama 原生格式解析失败**：SSE 分支中「缺少 `choices[0]` 就提前 return」的判断，导致 `{message:{content}}` / `{response:"..."}` 这类无 `choices` 的结构永远取不到文本。
- **设置页测试探针失真**：旧探针只发 8 个 token，遇到推理模型必然为空，会让用户误判为「连接失败」；且报错笼统为"格式异常"。现与真实生成共用解析与参数兼容逻辑，探针 Token 提高到 2048，并透传具体失败原因。
- **推理模型无正文**：deepseek-r1 / o1 / qwen-thinking 等的思考过程会消耗 `max_tokens`。现检测到该情况**自动把 Token 预算翻倍重试**，且思考内容与正文严格分离，不会写进笔记。
- **模型参数不兼容**：o1 / gpt-5 系列只认 `max_completion_tokens` 且不接受自定义 `temperature`，此前直接 400 失败。现自动改写参数并立即重试（不退避等待）。
- **`Unexpected token 'd', "data: {"id"... is not valid JSON`**：大模型接口返回 SSE 流式响应（`data: {...}`）时，`res.json()` 必然抛错。改为先读文本再容错解析——自动识别 SSE 并拼接 `delta.content`，同时兼容 ` ```json ` 包裹、前后带杂讯、以及 `content` 为数组的多模态响应；同时请求体显式带上 `stream: false`。
- **连接超时**：Obsidian 的三处请求与字幕代理请求此前**完全没有超时控制**，Obsidian 繁忙时会永久挂起。现全部接入统一超时（`fetchWithTimeout`），并把 `AbortError` 翻译为可读的中文提示。
- **自动截帧永久卡死**：YouTube 等流媒体的 `video.duration` 为 `Infinity` 时，会计算出无效时间点且无限等待 `seeked` 事件。现在时长不可用时自动切换为「连续采样」模式，每次 seek 增加 4s 超时兜底。
- **Service Worker 被回收导致无响应**：内容脚本的 `send()` 现按操作类型设置独立等待上限（生成 300s / 同步 120s / 导出 60s），并在通道类错误上自动重连一次。
- **B站字幕提取在网络异常时抛出无信息错误**：`proxyFetch` 的错误与超时现在会透传为可读文案；三层兜底请求各自捕获异常，不再因单层失败中断整个流程。
- **Obsidian 目录 404**：写入报目录不存在时，自动补建目录并重试一次（此前需用户手动建目录）。

### 新增
- **指数退避重试**：超时、429、5xx、网络抖动按 0.8s → 1.6s → 3.2s 自动重试；4xx 配置类错误不重试（避免无意义等待）。
- **Obsidian 连通性预检**：同步前先探测一次，把「服务未启动」与「密钥错误（401）」区分开，避免逐张图片重复失败；图片改为**分批并发上传**。
- **实时进度反馈**：后台重试时通过消息推送进度到面板，不再只有一句静态的「正在生成」。
- **设置项**：请求超时、失败重试次数、Obsidian 请求超时、字幕送入模型字符上限（超限保留首尾截断，显著降低长视频超时概率）、预建目录开关。
- **「测试 Obsidian 连接」按钮**：区分连不上与密钥错。
- **防重复提交**：生成/同步/导出期间禁用面板按钮，避免连点导致多个大模型请求并发叠加。

### 优化
- **解析逻辑抽为共享模块** `src/shared/llm-parse.js`：此前该逻辑在 `background.js` 与 `options.js` 各存一份，已出现行为漂移（一处修了另一处没修）。现由两处 `import` 共用，消除重复。为此 `options.html` 改为以 `type="module"` 加载脚本。
- **错误信息自诊断化**：所有解析失败路径都改为输出可排查的证据——分片分类计数、实际字段名、首个失败分片开头、`prompt_tokens`/`completion_tokens` 用量。对接不确定的第三方网关时，「解析不到预期结构」远比「解析报错」更难查。
- `base_url` 误填完整端点（`.../chat/completions`）时自动识别，不再拼成 `.../chat/completions/chat/completions`。
- 导出 ZIP 改由内容脚本转 Blob + objectURL 下载，绕开 Chrome 对 `data:` URL 下载约 2MB 的限制。
- 面板状态文案支持长文本换行；截帧时缓存设置，避免每帧一次扩展通信。

## [1.0.0] - 2026-08-22

### 新增功能
- 多平台适配：自动识别百度网盘、B站（bilibili.com）、YouTube（youtube.com），非支持平台隐藏面板。
- **面板按需打开**：打开视频页不再自动弹出操作面板；点击工具栏扩展图标 → 弹窗「打开笔记面板」才显示（幂等，可随时再次唤出）。
- 字幕提取：分平台抓取公开可见字幕，统一输出 `[{ time, text }]` 标准格式，面板内支持预览与手动编辑。
  - B站：优先官方 CC 字幕，其次 AI 自动字幕。
  - YouTube：优先官方上传字幕，其次自动生成字幕，默认取页面显示语言。
  - 百度网盘：优先读取播放器文本轨道 / 字幕渲染容器；实时捕获采用 `timeupdate` 事件驱动（跟随播放节奏，字幕切换不漏句）+ 800ms 轮询兜底，支持同源 iframe 内播放器与流式字幕渐进合并（消除 AI 字幕「短句→完整句」更新产生的碎片）；提取前自动补抓当前句并短暂重试；提取成功提示附「捕获至 X / 总时长 Y」进度，提示用户完整播放可补全。
- 关键帧截取：`<canvas>` 捕获播放器当前帧（纯前端本地），跨域时自动回退为可见标签页截图；支持手动与自动两种模式。
- 大模型接入：兼容 OpenAI `/v1/chat/completions` 标准接口；支持 `base_url / API Key / 模型 / temperature / 最大 token` 本地配置；完整中文错误处理与一键重试。
- 图文笔记生成：标准 Obsidian Markdown 输出，含 YAML 元数据、章节结构、配图引用；支持自定义提示词模板、YAML 字段、标签体系。
- Obsidian 同步：基于社区插件 `Local REST API` 本地接口通信，自动写入笔记与图片附件，返回 `obsidian://` 跳转链接；支持覆盖/新建选择。
- 基础交互：悬浮面板（提取字幕 / 生成 / 同步 / 复制 / 导出 MD+图片压缩包）、本地历史记录、SPA 路由切换自动刷新。

### 优化调整
- 严格遵循 Chrome Manifest V3，权限最小化（`storage / activeTab / scripting / downloads`），每个权限附用途注释。
- 纯原生 JavaScript / HTML / CSS 实现，零第三方依赖、无构建步骤、离线可用。
- 模块化架构：公共核心与分平台适配器分离，统一标准接口，便于扩展。

### 问题修复
- **字幕无法提取（核心修复）**：内容脚本直接 `fetch` 平台接口会因跨域（CORS）被拦截，导致三平台字幕均无法抓取。改为所有接口经**后台 Service Worker 代发（proxyFetch）**，彻底绕过 CORS。
- **B站 WBI 签名失败**：`x/player/wbi/v2` 需 WBI 签名，原自写 MD5 在第 4 轮（md5ii）存在常量错误，导致所有签名请求失败。已替换为经验证的 blueimp/JavaScript-MD5 实现，并保留「免签名 / 旧版 `x/player/v2`」两层兜底，提升不同视频的兼容性。
- **B站 cid 获取**：`x/web-interface/view` 代发时附带 `Referer` 与页面 `Cookie`，降低 `-412` 风控概率。
- **Obsidian 同步后提示「Vault not found」**：原因是在未探测到库名时使用了 `obsidian://open?path=...` 链接，Obsidian 无法据此定位 vault。已新增「库名（Vault）」设置项；优先使用用户填写的库名生成 `obsidian://open?vault=...&file=...`，未填写时仅显示同步成功路径、不再尝试打开，避免弹窗报错。
- **图片链接断链（图片已上传但笔记显示裂图）**：默认图片格式为 JPEG，上传文件名为 `frame_N.jpg`，而提示词让模型写 `frame_N.png`，旧替换映射 key 为 `frame_N.jpg`，导致 markdown 内的 `frame_N.png` 永远匹配不上、链接失效。已为每帧注册 `frame_N` / `frame_N.png` / `frame_N.jpg` 三个别名统一替换；ZIP 导出同步采用相同逻辑。
- **Obsidian 中提示「找不到 frame_N.png」**：markdown 内写入的是 vault 绝对路径（如 `VideoNotes/B站/attachments/frame_2.jpg`），但 Obsidian 默认按**相对当前 md 文件**解析图片链接，导致路径解析错误。已新增 `getRelativePath()` 计算图片相对笔记目录的相对路径（如 `./attachments/frame_2.jpg`），并新增 `ensureDir()` 在同步前自动创建附件目录（失败则降级把图片放到笔记同目录），确保图片真实存在且链接可解析。
- **导出 ZIP 报错 `URL.createObjectURL is not a function`**：Service Worker 无 DOM API，无法使用 `URL.createObjectURL`。已新增 `bytesToBase64()`，将 ZIP 字节流转为 base64 data URL 后调用 `chrome.downloads.download`。
- **点击历史记录报错 `$ is not defined`**：`$` 只在 `bindEvents()` 内部定义，`loadHistory()` 越级访问导致未定义。已改为 `panelEl.querySelector(...)`。
- **图片引用扩展名重复（如 `./frame_1.jpg.png`）**：多别名 `frame_N / frame_N.png / frame_N.jpg` 顺序替换时，`frame_1` 作为前缀先命中了 `frame_1.png`，导致结果变成 `./frame_1.jpg.png`。已改为**两阶段替换**：先把所有别名统一替换成临时占位符 `__VNH_IMG_N__`，再一次性替换为真实路径。`syncToObsidian` 与 `exportZip` 均已同步修改。
- **多视频图片互相覆盖**：原实现把所有图片放在 `VideoNotes/平台/` 或 `VideoNotes/平台/attachments/` 下，不同视频的 `frame_1.jpg` 会互相覆盖。已改为**每篇笔记独立子目录**：`VideoNotes/平台/笔记标题/笔记标题.md`，图片放在 `VideoNotes/平台/笔记标题/attachments/` 下，markdown 内引用 `./attachments/frame_N.jpg`。`ensureDir()` 同时改为逐层创建目录，兼容 Local REST API 无法一次创建多级目录的情况。
- **笔记结构美化**：新增 `buildFrontmatter()` 按设置字段与真实数据生成规范 YAML 元信息头，并自动拼接 `# 标题`；系统提示词改为只输出正文（不重复 YAML/标题），要求分章小标题、列表要点、表格对比、Obsidian Callout 突出重点，末尾以 `> [!summary]` 给出要点回顾。
- **百度网盘字幕提取失败**：原实现仅依赖 MutationObserver 读变动节点自身文本（字幕常被拆子节点而漏抓），且 `findSubtitleRoot` 只搜主文档、百度播放器常在同源 iframe 内导致根本找不到字幕节点。已重写为「轮询读当前字幕文本（每 800ms）+ 观察器触发」双保险，并同时遍历 `document` 与同源 `iframe.contentDocument`；新增 `scoreText()` 打分从候选文本中挑出真正的字幕（排除倍速/全屏等 UI 文字）；提取失败提示改为可操作步骤（开启字幕→开启 AI 字幕→播放→再提取）。
- **YouTube 字幕解析**：`ytInitialPlayerResponse` 改用平衡括号扫描提取，避免正则对超大内联 JSON 失效；字幕下载同样走后台代发。
- **百度网盘字幕**：新增对播放器实时字幕的 `MutationObserver` 捕获，并保留 `textTracks` / DOM 兜底路径。
